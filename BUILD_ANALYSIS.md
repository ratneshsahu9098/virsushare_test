# BUILD_ANALYSIS.md — virusShare packaging analysis

Written as Phase 1 of the packaging conversion (PyInstaller + Inno Setup).
All findings come from inspecting the repository, not from assumptions.

---

## 1. Entry point

| Item | Value |
|---|---|
| Entry point | `app.py` → `main(argv)` (line 276), guarded by `if __name__ == "__main__"` |
| CLI flags | `--version`, `--minimized`, `--verbose`, `--transfer-port`, `--discovery-port`, `--no-discovery` |
| Windowed app? | Yes — Qt `QApplication` event loop (`app.py:490`) |
| Headless mode | `--version` / already-running dialog must not require a console |

`app.py` imports `gui.*` lazily inside `main()` (after `QApplication` setup), so a
static analyzer/PyInstaller hook graph can miss them — see §6.

## 2. GUI framework

- **PySide6 6.11.2** (Qt 6 for Python), modules used:
  `QtCore`, `QtGui`, `QtWidgets`, `QtSvg` (icon rendering), `shiboken6` (bindings).
- Threading rule: workers never touch widgets; cross-thread traffic goes through
  `gui/bridge.py::ThreadBridge` (queued signals) — irrelevant to packaging but it
  means no extra Qt threading modules are pulled in at runtime.
- `conftest.py` sets `QT_QPA_PLATFORM=offscreen` for tests only; the packaged exe
  uses the default Windows platform plugin (`windows`).

## 3. Database

- **SQLite via the stdlib `sqlite3`** (no driver package needed).
- File: `%APPDATA%\virusShare\history.db` (WAL journal, `database/history.py`).
- Created on first launch; written by the GUI thread and worker threads
  (own `RLock`).

## 6. Dynamic imports PyInstaller may miss

`virusShare.spec` already lists these as `hiddenimports` because they are
imported *inside functions*:

```
gui.bridge, gui.styles, gui.icons, gui.device_panel, gui.transfer_queue,
gui.role_screen, gui.sender_screen, gui.receiver_screen, gui.pairing_dialog,
gui.conflict_dialog, gui.history_dialog, gui.settings_dialog, gui.tray,
gui.main_window, database.history, transfer.manager, utils.windows,
utils.network, utils.formatting, utils.logger
```

Additional lazy imports observed in source:

- `app.py`: `utils.windows.remove_legacy_autostart`, `utils.logger.setup_logging`,
  `core.config.get_settings`, `core.security.*`, `network.*`, `PySide6.QtWidgets`,
  `gui.*`, `database.history`, `transfer.manager` — all inside `main()`.
- `scripts/make_release_assets.py`: `PyInstaller.utils.win32.versioninfo` and
  `gui.icons.write_ico` — **build time only**, must not ship as a runtime dep.
- `gui/bridge.py:181`: `from transfer.receiver import ...` inside a closure.
- `core/security.py` / `network/session.py`: `cryptography.*` imported at module
  scope (auto-detected).

**Verdict:** the existing `hiddenimports` list is adequate; the real proof is the
Phase 9 launch test of the built exe.

## 9. Known build/test problems

> **Status (end of packaging work): all five items below are resolved.**
> 1 → fixed (cyclic GC destroyed live Qt windows during event dispatch;
> `app.py` suspends GC around `exec()`/shutdown, `conftest.py` keeps GC out
> of dispatch — full suite 434 passed / 1 skipped, repeated green runs);
> 2 → `installer/virusShare.iss` (Phase 6); 3 → `virusShare.spec` onedir
> (Phase 3); 4 → `build_windows.bat` venv/clean/test-gate/verify/ISCC
> (Phase 7); 5 → assets under `resources/` (Phase 4).

1. **Native access violation in the test suite.** `python -m pytest -q` aborts
   ~49 % in `test_startup_failure_after_bind_shuts_everything_down`
   (`tests/test_release.py`) with `Windows fatal exception: access violation`
   while the main thread is inside `QApplication.processEvents()` (via
   `transfer/manager.py:613` → `app.py:249`). 433 tests collect; 412 pass when
   `test_release.py` is excluded; `test_release.py` passes 20/20 in isolation.
   First candidate fix (never `close()` a socket another thread is parked in —
   `network/tcp_server.py::stop`) is applied but did **not** clear the fault, so
   the root cause is still open (tracked as Phase 9 work).
2. **No installer** (Phase 6 will add `installer/virusShare.iss`).
3. **onefile only** (Phase 3 switches production build to onedir).
4. Build script lacks venv/clean/verify/installer steps (Phase 7).
5. Icon/version assets live in `assets/` while the target layout wants
   `resources/icons/` (Phase 4).

## 10. Recommended packaging method

**PyInstaller `onedir` + Inno Setup 6** (as recommended):

- `onedir` → `dist/virusShare/virusShare.exe` + `_internal/`: fast cold start,
  no per-launch unpack of 49 MB, trivially updatable, and the layout Inno Setup
  expects for `{autopf}\virusShare\`.
- **Inno Setup 6** → `dist/installer/virusShare-Setup.exe`: Start Menu +
  optional Desktop shortcut, Add/Remove Programs entry, `asInvoker` manifest,
  uninstall that preserves user data by default.
- Keep an **optional onefile** target (separate spec or a spec flag) for
  portable use, but never for the installer payload.
- Exclusions already in the spec (WebEngine, Quick/Qml, Charts, Multimedia,
  Sql, Test, tkinter …) stay — they keep the bundle lean.
- Everything user-writable stays under `%LOCALAPPDATA%\virusShare\` (Phase 2);
  Program Files receives only application files.
